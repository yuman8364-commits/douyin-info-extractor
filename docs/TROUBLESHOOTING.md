# 故障排查

## 打开工具就出现 Windows 安全提示

当前 EXE 未做代码签名，首次运行可能触发 SmartScreen 或安全软件提示。请确认文件来自本项目发布页或可信构建，不要从未知来源下载。需要面向更多用户分发时，应先增加正式代码签名。

## `提取记录.xlsx` 被占用时 Excel/WPS 被关闭

这是用户主动提取和手动强刷的预期行为。为了确保新链接和数据能写入，工具会执行强制关闭并重试保存。Microsoft Excel 的 `EXCEL.EXE` 和 WPS 表格的 `et.exe` 会全部结束，因此操作前应保存其它工作簿。

如果自动关闭后仍然写入失败：

1. 在任务管理器确认没有该工作簿的遗留 Office 进程。
2. 检查输出目录和工作簿是否只读。
3. 检查杀毒软件、同步盘或备份软件是否短暂锁定文件。
4. 查看 `提取日志.log` 中的强制关闭和二次写入记录。

工具启动时不会自动刷新。只有用户主动点击提取、重试或“刷新记录”才会联网和写表。

## 导入旧文档失败

- 只支持 `.xlsx` 和 `.xlsm`。
- 文档至少应包含“视频链接”和“顺序”表头。
- 损坏、加密或只有未知表头的工作簿不会被猜测性修改。
- 导入操作始终只读；失败或取消后，当前输入框内容保持不变。

`2.0.3` 已修复导入成功后日志器未初始化导致的弹窗，请先确认版本。

## 为什么没有生成新的备份目录

“备份文件”默认不勾选，所以成功写表或替换媒体后不会新增长期备份。需要保留本次操作前的旧工作簿、媒体、封面或文案时，请在点击提取/刷新前勾选该选项。未勾选不影响失败自动回滚，已有的 `表格备份` 和 `替换备份` 也不会被删除。

## 删除记录后后续编号发生变化

这是预期行为。删除中间记录后，上方输入会连续编号，因此 Excel 中后续“顺序”值以及视频、图集目录、封面和文案文件名也必须整体前移一位。否则下一次提取会把新数据写到错误作品上。

删除可从下方记录的右键菜单、键盘 Delete 或“编辑 → 删除选中记录”触发，并有二次确认。若勾选“备份文件”，目标关联文件位于 `删除备份`；默认未勾选时成功删除不可恢复。删除失败提示“已恢复原记录文件”时，原编号和文件应保持不变。

## 抓取失败或提示风控/结构变化

先确认作品仍是公开内容。HTTP 请求命中“验证码中间页”时，工具会立即停止重试并弹出独立 Edge/Chrome 窗口；请在 5 分钟内人工完成验证。工具不会读取日常浏览器资料，也不会自动破解验证码。

可以：

1. 在弹出的工具专用浏览器中完成验证，不要关闭窗口。
2. 若提示浏览器资料被占用，关闭上次遗留的工具专用 Edge/Chrome 窗口后重试；不要结束日常浏览器。
3. 验证失败后批次会暂停，当前记录写入真实状态，后续“未检查”记录保持原样。
4. 检查系统时间、代理、防火墙和 DNS，并复制日志中的版本号、作品 ID 和失败阶段进行诊断。

不要导入日常浏览器 Cookie，也不要使用自动验证码绕过；这些能力不在项目支持范围内。

## 下载后得到的不是有效视频或图片

当前下载器会检查状态码、`Content-Type`、实际字节数和图集张数，并先写 `.part`。如果仍发生异常：

1. 保留已脱敏的日志。
2. 检查 `.staging` 是否已被自动清理。
3. 不要手动覆盖旧成果；先查看 `替换备份`。
4. 添加一个不包含真实个人数据的故障注入测试后再修改校验规则。

## 刷新记录后媒体没有重新下载

这是预期行为。“刷新记录”只更新公开元数据及工作簿；只有新作品通过“全部提取”“单次提取”或“重试失败项”时才会进入媒体下载流程。

## 右侧封面变形或挤压界面

`2.0.2` 起预览容器固定为 `190×250`，图像在 `170×230` 画布内保持比例居中。若旧版仍有问题，请升级到 `2.0.3`，并确认运行的不是被其它目录中的旧 EXE。

## 点击停止后没有立刻退出

停止是协作式取消。工具需要等当前网络块或文件提交进入安全点，再清理 `.part/.staging` 并恢复界面。这个过程用于避免留下半截媒体或损坏工作簿。

如果长时间没有结束，请保存 `提取日志.log`，但不要强制结束进程，除非确认输出目录已有额外备份。

## 构建脚本提示文件被占用

完全退出旧版 `抖音信息提取工具.exe`，确认任务管理器中没有同名进程，再执行：

```powershell
pwsh -File .\构建发布版.ps1
```

脚本会复用项目内的 `.build-venv`。依赖版本来自 `requirements.txt` 和 `requirements-build.txt`。

## 发布隐私检查失败

不要绕过检查。确认发布目录的：

- `data/config.json` 内容为 `{}`；
- `data/input_cache.txt` 只有空编号占位 `1.`；
- `data/browser_profile` 不存在，发布包不得携带 Cookie 或浏览器缓存；
- 没有真实 URL 或 `C:\Users\用户名` 路径。

删除旧的个人化发布目录后重新构建。源码根目录中的个人状态也不得提交到 Git。
