# 故障排查

## 打开工具就出现 Windows 安全提示

当前 EXE 未做代码签名，首次运行可能触发 SmartScreen 或安全软件提示。请确认文件来自本私有仓库的可信构建，不要从未知来源下载。需要面向更多用户分发时，应先增加正式代码签名。

## 提示 `提取记录.xlsx` 被占用

关闭正在打开该文件的 Excel/WPS 窗口，然后点击重试。工具不会自动结束 Excel/WPS，因为这样可能关闭其它尚未保存的工作簿。

如果关闭后仍然提示：

1. 在任务管理器确认没有该工作簿的遗留 Office 进程。
2. 检查输出目录和工作簿是否只读。
3. 检查杀毒软件、同步盘或备份软件是否短暂锁定文件。
4. 查看 `提取日志.log` 中标记为 `workbook` 的失败阶段。

## 导入旧文档失败

- 只支持 `.xlsx` 和 `.xlsm`。
- 文档至少应包含“视频链接”和“顺序”表头。
- 损坏、加密或只有未知表头的工作簿不会被猜测性修改。
- 导入操作始终只读；失败或取消后，当前输入框内容保持不变。

`2.0.3` 已修复导入成功后日志器未初始化导致的弹窗，请先确认版本。

## 抓取失败或提示风控/结构变化

先确认作品在未登录浏览器中仍可公开访问。工具会区分网络失败、风控响应和页面结构变化，不会把“暂时没有解析到数据”直接写成已删除。

可以：

1. 稍后使用“重试失败项”。
2. 减少单批数量，保留串行随机间隔。
3. 检查系统时间、代理、防火墙和 DNS。
4. 复制日志中的版本号、作品 ID 和失败阶段进行诊断。

不要通过导入账号 Cookie 或自动绕过验证码来处理，这些能力不在项目支持范围内。

## 下载后得到的不是有效视频或图片

当前下载器会检查状态码、`Content-Type`、实际字节数和图集张数，并先写 `.part`。如果仍发生异常：

1. 保留已脱敏的日志。
2. 检查 `.staging` 是否已被自动清理。
3. 不要手动覆盖旧成果；先查看 `替换备份`。
4. 添加一个不包含真实个人数据的故障注入测试后再修改校验规则。

## 强制刷新后媒体没有重新下载

这是预期行为。“强制刷新记录”和启动时的已有记录刷新只更新公开元数据及工作簿；只有“全部提取”“单次提取”或“重试失败项”会进入媒体下载流程。

## 右侧封面变形或挤压界面

`2.0.2` 起预览容器固定为 `190×250`，图像在 `170×230` 画布内保持比例居中。若旧版仍有问题，请升级到 `2.0.3`，并确认运行的不是被其它目录中的旧 EXE。

## 点击停止后没有立刻退出

停止是协作式取消。工具需要等当前网络块或文件提交进入安全点，再清理 `.part/.staging` 并恢复界面。这个过程用于避免留下半截媒体或损坏工作簿。

如果长时间没有结束，请保存 `提取日志.log`，但不要强制结束进程，除非确认输出目录已有额外备份。

## 构建脚本提示文件被占用

完全退出旧版 `抖音信息提取工具.exe`，确认任务管理器中没有同名进程，再执行：

```powershell
pwsh -File .\构建发布版.ps1
```

脚本会复用项目内的 `.build-venv`。依赖版本来自 `requirements.txt` 和 `requirements-build.txt`。

## 发布隐私检查失败

不要绕过检查。确认发布目录的：

- `data/config.json` 内容为 `{}`；
- `data/input_cache.txt` 只有空编号占位 `1.`；
- 没有真实 URL 或 `C:\Users\用户名` 路径。

删除旧的个人化发布目录后重新构建。源码根目录中的个人状态也不得提交到 Git。
