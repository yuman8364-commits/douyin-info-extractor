# 抖音提取工具｜Douyin Info Extractor

面向 Windows 的抖音公开作品批量整理工具。它可以从分享文本或链接中解析公开的视频/图文作品，下载媒体和封面，把作品信息安全写入 Excel，并保留人工填写的业务分类和文案。

当前版本：`2.0.20`

> 本项目只支持公开作品，不提供 Cookie 导入、私密内容访问或自动验证码破解。公开页触发平台验证时，可在工具弹出的独立浏览器中由用户人工完成验证。使用者应遵守平台规则、版权要求和当地法律。

## 核心能力

- 批量提取：按锁定序号依次处理多条分享文本或链接；表格已有记录只强制刷新 Excel，不进入媒体下载。
- 单次提取：只处理光标所在条目，不影响其它输入；已有记录同样只强制刷新 Excel。
- 纯链接整理：从混合分享文案中提取链接，按首次出现顺序去重。
- 旧文档导入：只读选择以前生成的 `xlsx/xlsm`，按“顺序”列回填链接，不联网、不修改源文档。
- 公开作品解析：识别视频和图文，记录规范链接、作品 ID、标题、标签、点赞、评论、作者和更新时间。
- 媒体落盘：视频保存为 MP4；图文按序保存为图片目录；封面单独保存并嵌入记录表。
- 工作簿增量更新：只修改工具管理的行与列，保留其它工作表、额外列、格式和人工内容。
- 安全替换：媒体、封面和工作簿先暂存，全部验证成功后提交；失败会回滚旧成果。
- 可选长期备份：“备份文件”默认不勾选；勾选后才长期保留表格及被替换媒体、封面和文案的副本。
- 同步删除：右键下方已提取记录或按 Delete，经确认后同步删除输入链接、Excel 行、媒体、封面和文案，并连续重排后续顺序。
- 可取消任务：下载块、重试等待和批次间隔都能响应停止；关闭窗口时会等待清理完成。
- 失败项重试：批次结束后可以只重试失败记录。
- 刷新写表：全部提取、单次提取和“刷新记录”都会重新抓取公开元数据并原子写回 Excel；“刷新记录”每检查完一条就实时更新界面和 Excel，不等待整批结束；只要表格已有该链接或作品 ID，即使媒体缺失也绝不补下载或替换媒体。
- 刷新结果标色：更新中的当前行与刚成功的行显示绿色，失败行显示红色；整批结束后正常/已恢复记录恢复无色，失败记录常驻红色。先前标记失效的链接重新可用时，状态写为“已恢复”。
- 失败状态写回：已有作品本次抓取失败时保留旧标题、互动数和人工字段，但“状态”会改为本次失败原因，不再继续显示“正常”。
- 验证码熔断：识别验证码页后不再高频重试；浏览器验证未完成时只标记当前记录，后续记录保持未检查。
- 网络容错：短链和作品页遇到连接/TLS/DNS/超时或 408/5xx 时执行有限退避重试；封面、图集和视频流中断时重试同一地址，Requests 链路持续失败则复用应用专用浏览器网络。
- 主动联网：启动工具不会自动刷新，只有点击提取、重试或“刷新记录”才访问网络。
- 固定封面预览：右侧预览区固定为适中的尺寸，封面保持比例显示，不再挤压界面。
- 发布隐私保护：构建包只生成空白配置和空输入模板；检测到 URL 或本机用户路径时构建失败。

## 环境要求

- Windows 10 或 Windows 11，64 位。
- Python 3.11 或更高版本（从源码运行或构建时需要）。
- PowerShell 7 推荐用于构建；Windows PowerShell 也可执行脚本。
- 可访问抖音公开分享页及其公开媒体地址的网络。
- 已安装 Microsoft Edge 或 Google Chrome；仅在公开页要求人工验证时弹出应用专用浏览器窗口。
- Excel/WPS 不是运行必需项。用户主动提取或手动刷新时，如果 `提取记录.xlsx` 被占用，工具会强制关闭全部 Excel/WPS 表格进程后重试写入；请先保存其它工作簿。

## 快速开始

### 使用发布版

1. 获取完整的 `抖音信息提取工具` 发布目录，不要只复制其中的 EXE。
2. 双击 `抖音信息提取工具.exe`。
3. 粘贴分享文本或链接，选择输出目录，点击“全部提取”。

若抖音返回验证码中间页，工具会弹出独立的 Edge/Chrome 窗口。请在 5 分钟内人工完成验证，不要关闭该窗口；验证成功后同一批次会复用该会话。该窗口不读取日常浏览器资料。

“备份文件”默认不勾选。未勾选时，事务仍会暂存旧文件以便失败回滚，但成功后不会新增长期备份；已有备份不会被删除。

发布版是便携目录。若 EXE 所在位置不可写，运行状态会改用 `%LOCALAPPDATA%` 下的可写目录，并在界面中给出提示。

### 从源码运行

在 PowerShell 7 中执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

如果系统没有 `py` 启动器，可把第一条命令改为 `python -m venv .venv`。

## 使用说明

### 输入与序号

输入框按以下形式维护任务：

```text
1. https://v.douyin.com/……
2. 复制的分享文案和其中的链接
3. https://www.douyin.com/video/……
```

序号由工具锁定，用于决定文件名和 Excel 中的“顺序”。只修改序号后的内容。粘贴已在列表中的链接时，工具会提示它现在的序号并阻止重复添加。

### 常用操作

- **全部提取**：依次处理输入框中的全部有效条目。
- **单次提取**：只处理光标所在条目。
- **刷新记录**：刷新已有记录的标题、互动数、作者等信息，不重复下载媒体；每条完成后立即更新界面和 Excel，成功暂时标绿、失败标红，完成后仅失败行保留红色。
- **打开提取记录**：直接打开当前输出目录里已有的 `提取记录.xlsx`；文件不存在时只提示，不创建空表。
- **停止任务**：请求安全取消；当前操作会清理暂存文件后停止。
- **重试失败项**：只重新运行上一批失败的条目。
- **备份文件**：默认不勾选；勾选后，本次任务成功时长期保留旧表格及被替换文件。
- **删除当前链接**：先把光标放在上方要删除的输入条目中，再点击输入区右上角按钮（或按 `Ctrl+Delete`）。未提取链接只从上方移除；已提取链接会先要求确认，然后同步删除下方记录、Excel 行及关联文件。删除后只将它后面的序号依次前移，前面序号不变。
- **手动擦除已提取链接**：在输入框里使用退格、Delete、剪切或粘贴替换导致已提取链接消失时，工具会先恢复该条并弹出同步删除确认；只有确认后才会同时更新上方、下方、Excel 和关联文件。
- **删除选中记录**：选中下方记录后点击顶部“删除选中记录”按钮，也可右键、按 Delete 或使用“编辑”菜单；确认后同步删除输入链接、Excel 行、媒体、封面和文案，并将后续记录与文件名整体前移。
- **从已有文档导入链接…**：按旧记录表的“顺序”读取链接并显示到输入框；不会修改被选择的文件。
- **提取纯链接**：将混合文本中的链接按出现顺序整理后复制。

### 输出目录

```text
输出目录/
├─ 提取记录.xlsx
├─ 爆款视频/
│  ├─ 1.mp4
│  └─ 2/                 # 图文作品图片目录
├─ 文案提取/
│  └─ 1.txt              # 视频文案载体；已有人工文案不会被覆盖
├─ 封面/
├─ 表格备份/             # 勾选“备份文件”时保留最近 5 份工作簿备份
├─ 替换备份/             # 勾选后保留被替换媒体、封面和文案
├─ 删除备份/             # 勾选后保留被删除记录的关联文件
└─ 提取日志.log          # 自动轮转的运行日志
```

正常完成或取消后，临时 `.staging` 和 `.part` 文件应被清理。异常断电后如仍有残留，可在确认没有任务运行时手动删除。

发布版会在自身 `data/browser_profile/`（便携目录不可写时为 `%LOCALAPPDATA%`）保存工具专用的浏览器验证状态。该目录可能包含 Cookie，只应保存在本机，不应提交、分享或打入发布包。

## Excel 数据模型

工具管理的工作表名优先为“提取记录”，字段如下：

| 字段 | 含义 | 覆盖规则 |
|---|---|---|
| 视频链接 | 原始输入或规范链接 | 工具更新 |
| 标题 | 作品标题 | 工具更新 |
| 标签 | 作品标签 | 工具更新 |
| 点赞数 | 抓取时的公开点赞数 | 工具更新 |
| 评论数 | 抓取时的公开评论数 | 工具更新 |
| 类型 | 人工业务分类 | 视为人工字段，默认“基本盘” |
| 博主 | 作者昵称 | 工具更新 |
| 状态 | 提取或刷新状态 | 工具更新 |
| 封面 | 嵌入的封面图片 | 工具更新 |
| 顺序 | 输入编号和文件编号 | 工具维护 |
| 作品ID | 抖音作品唯一 ID | 去重主键 |
| 作品形式 | `video` 或 `note` | 工具更新 |
| 最后更新 | 最近成功抓取时间 | 工具更新 |

旧版 9/10 列工作簿会按表头名称迁移。其它工作表、额外列和已有格式会尽量保留；只有勾选“备份文件”时才会长期备份原工作簿。

## 数据安全设计

一次作品写入按事务处理：

1. 解析作品并核对返回数据中的作品 ID。
2. 媒体和封面下载到同盘 `.staging`，使用 `.part` 临时文件。
3. 校验 HTTP 状态、内容类型、实际字节数和图集张数。
4. 将旧媒体、旧封面及需要替换的文案移入临时回滚区；勾选备份时成功后保留，否则删除。
5. 新工作簿写入临时副本，并验证可以重新打开。
6. 所有步骤成功后原子替换正式文件；任一步失败则恢复旧文件并记为失败。

同类型视频替换不会清空已有文案。视频与图文互换时会移走冲突文件；未勾选备份时，成功提交后旧冲突文件不可恢复，但提交失败仍会自动回滚。用户主动点击提取、重试或刷新时，若工作簿被占用，工具会执行 `taskkill /F` 关闭全部 Microsoft Excel 和 WPS 表格进程并重试写入；这可能丢失其它未保存工作簿。工具启动时不会联网或写表。

删除第 N 条记录时，工具会先把第 N 条及后续关联文件移入同盘暂存区，删除 Excel 对应行，再把后续记录、媒体、图集目录、封面和文案的顺序整体前移一位。任一步失败会恢复原文件；成功后按“备份文件”选项决定保留到 `删除备份` 还是永久清理。上方输入仅删除链接匹配的条目，找不到匹配链接时不会误删同位置的其它输入。

## 构建 Windows 发布版

建议使用 PowerShell 7：

```powershell
pwsh -File .\构建发布版.ps1
```

构建脚本会：

- 在项目内创建隔离的 `.build-venv`；
- 安装锁定版本的运行和构建依赖；
- 使用 PyInstaller 生成无控制台的 64 位目录版；
- 写入版本号和构建时间；
- 创建空白 `data/config.json` 和 `data/input_cache.txt`；
- 扫描 URL、本机用户路径和非空缓存，未通过时终止构建。

产物位置：`dist/抖音信息提取工具/抖音信息提取工具.exe`。

构建时如果提示输出文件被占用，请先完全退出正在运行的旧版 EXE，再重新执行脚本。

## 自动化测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试覆盖：

- 输入编号、分享文本拆分、纯链接保序去重；
- 旧文档导入、按顺序回填和取消/异常保护；
- 作品 ID 匹配、规范链接和响应校验；
- 旧表迁移、按作品 ID 去重和人工字段保留；
- 视频/图文事务替换、记录同步删除与重排、可选长期备份、文案保护及失败回滚；
- 取消、验证码熔断、固定封面预览；
- 构建脚本隐私规则和发布状态扫描。

GitHub Actions 会在 Windows + Python 3.11 环境中运行同一套测试。

## 项目结构

| 路径 | 职责 |
|---|---|
| `app.py` | Tkinter 界面、任务编排、结果展示和安全退出 |
| `extractor.py` | 短链解析、页面数据解析、作品 ID 核验及媒体下载 |
| `exporter.py` | Excel 按表头迁移、增量更新、封面嵌入和原子保存 |
| `storage.py` | 媒体暂存、备份、提交和失败回滚 |
| `input_parser.py` | 编号输入、分享文本拆分、纯链接整理和旧表链接导入 |
| `tasking.py` | 结构化任务消息、取消事件和可中断等待 |
| `tests/` | 单元测试和故障注入测试 |
| `构建发布版.ps1` | 隔离环境构建及发布隐私检查 |
| `docs/` | 架构和故障排查文档 |

更详细的内部流程见 [架构说明](docs/ARCHITECTURE.md)，常见问题见 [故障排查](docs/TROUBLESHOOTING.md)。

## 已知限制

- 抖音页面结构、接口和风控策略可能变化；解析结构变化会以失败记录呈现，不会猜测为“已删除”。
- 只处理公开作品；没有登录态支持，也不承诺处理地区限制、年龄限制或其它受限内容。
- 批量任务保持串行并带随机间隔，优先稳定性而非速度。
- 真实公开视频流程已经验收；真实图文作品仍建议在目标 Windows 环境中补一次端到端验收。
- 发布 EXE 当前未做代码签名，Windows 首次运行可能显示来源或安全提示。
- 下载和使用媒体时，版权、隐私和平台合规责任由使用者承担。

## 隐私与仓库卫生

仓库不应包含：

- `config.json`、`input_cache.txt` 和运行日志；
- 真实的 `提取记录.xlsx`；
- 下载的视频、图片、封面、字幕或人工文案；
- `dist/`、`build/`、虚拟环境和本机进度文件。

提交前请检查 `git status`，不要使用真实 URL、本机用户路径或个人数据作为测试夹具。
